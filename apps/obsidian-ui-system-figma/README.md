# Obsidian UI System for Figma Design

This local Figma Design plugin generates the currently implemented UI Kit on a managed page with one **Figma Package v1 ZIP** and one **Generate UI Kit** action. The ZIP supplies the 59 captured specimens across 26 public API families in its captured Dark or Light mode. Versioned, tracked Dark probe fixtures supply the implemented File Explorer rows, Folder Rows, View Header, Workspace Tab, Side Panel, Search View, Files View, Bookmarks View, and Outline View; a paired Dark/Light appearance fixture supplies known mode values. The action calls generators in dependency order, creates separate hosted Search, Files, Bookmarks, and Outline previews, and adds public API Controls, Settings and Overlays sections. The user confirmed that the corrected broad public batch generates in Figma Desktop; detailed visual validation remains open.

Button, Search, the File Explorer rows, View Header, Workspace Tab, Side Panel, and the first hosted Search composition have been confirmed in Figma Desktop for their documented samples. The user also accepted the component reuse revision and unified one-action flow on 2026-10-02. [Component reconstruction rules](../../docs/obsidian-ui-system-figma/components/component-reconstruction.md) and the [UI system map](../../docs/ui-system-map.md) describe their scope.

## Build, install, and generate

1. From the repository root, run `npm ci` if dependencies are missing, then `npm run build --workspace @obsidian-ui-system/figma-plugin`.
2. In Figma Desktop, open a **Figma Design** file and import `apps/obsidian-ui-system-figma/manifest.json` through **Plugins → Development → Import new plugin from manifest…**. Reopen the development plugin after rebuilding. If a changed `src/ui.html` is not picked up, re-import the manifest.
3. Use an existing complete Package v1 ZIP in `dev-vault/obsidian-ui-exports/figma-packages/`, such as `obsidian-ui-package-2026-10-03T17-04-24-930Z.zip` (Dark). The public batch requires all 59 previously captured specimens; no new Obsidian capture is needed.
4. In a new file, start on a blank Figma page. For the known legacy full kit, start anywhere in that file. Run **Obsidian UI System**, select that **Package v1 ZIP**, wait for the package summary, and click **Generate UI Kit**. Later runs reuse the managed kit page, even if started from another page. No standalone probe JSON is selected in Figma.

The action creates `Obsidian / Button`, `Obsidian / Search`, `Obsidian / Icon Button`, and `Obsidian / Tree Navigation Row` Component Sets, then the hosted Search, Files, Bookmarks, and Outline compositions and the public API batch. One `Obsidian UI / Appearance` Variable collection supplies Dark/Light appearance to the generated Components, icon sources and previews. Primitive color roles are aliases of matching global roles; the kit also creates one `Obsidian / Glyph / …` Component per distinct observed SVG geometry. Icon Button swaps those glyph Components while action names stay on its consuming instances. Workspace Tab and Sidedock glyph wrappers, Close, Search Disclosure/More, Bookmarks rows, Tree Navigation Row disclosure and new public icon uses contain instances of canonical glyphs. Files uses Tree Navigation Row variants for the observed Folder and File states/depths; JSON/ZIP remain editable metadata. Outline uses the same set with wrapping and automatic height. The Views use the Side Panel's `Hosted View` and `Tab group` swaps at 242 and 200 px; temporary 300 px instances check further resize. The original Side Panel preview remains intact. The unrelated `Outline probe` sample is excluded from Search.

The focused Search extension also generates global `Obsidian / Toggle` and `Obsidian / Tooltip` Components from captured public specimens. Search-specific components cover compact Match case and Settings states, result count/menu indicator, the small Sort Select, open options, and short/expanded result context with hover. Search keeps using the same Filled Search and hosted Side Panel contracts. A separate hosted preview shows Search options open, and a context preview displays a reusable Tooltip instance. These additions await Figma Desktop visual validation.

The public API batch reuses those sources and adds native sets for captured input, setting, menu, notice and suggestion states. Text labels and values become Component Properties where useful; nested instances expose their properties only when Figma permits it. Suggestion Item and Prompt Input are shared only where the captured structures repeat. Known paints bind directly to Appearance Variables, including eight paired public roles newly added to the collection. `PopoverSuggest` is represented by its captured empty shell; Menu checked and Display Value warning lack exact SVG path evidence for their marks. Color picker chrome and unobserved states are outside this batch. The three public sections are managed by the existing file-wide regeneration lifecycle. The first Desktop run stopped at an invalid bare-instance exposure; the correction generated successfully in Figma Desktop. Detailed per-family visual, property, resize and repeated regeneration checks remain open.

The managed page starts with that collection explicitly in **Dark**, regardless of the ZIP's captured mode. To switch the generated kit, deselect the canvas, then use **Page → Apply variable mode → Obsidian UI / Appearance → Light** in Figma's right sidebar. Choose Dark there to return. You can also select one Component Set or preview frame and use **Appearance → Apply variable mode** to change only that object and its nested instances. Regeneration builds a replacement on the managed page and moves external instances to its Components before removing the prior managed roots.

One file-wide manifest records the managed page and generated root IDs. Shared plugin data on every managed node verifies ownership before replacement; unrelated homonyms and user nodes outside managed roots are preserved. Regeneration uses the same compatible `Obsidian UI / Appearance` collection and Variable IDs across pages. A handled failure before replacement removes the new roots and restores reused Variables. For the last pre-ownership full-kit format, the first run performs a read-only preflight and then compares complete old generations with the staged output: Component properties, nesting, observed glyph geometry, Variable roles and internal instance references must all match. It migrates external instances and their text/state/icon properties before deleting those old masters. Multiple complete legacy generations across pages can converge to the same new managed kit. Incomplete, altered or unrelated nodes stop the action with the specific mismatch; names alone never authorize deletion. Recognized duplicate Variable collections, including the legacy `Obsidian UI / Navigation primitives` name, are rebound and removed only when no bindings or aliases remain. See the [component reconstruction guide](../../docs/obsidian-ui-system-figma/components/component-reconstruction.md) for lifecycle rules. The ZIP importer checks format, schema `0.4.0`, supported layout model, capture context, required tokens, and Button/Search evidence before enabling generation. The internal fixtures are checked before Figma nodes are created. The plugin does not read the local filesystem directly or access the network; its Custom UI reads the selected ZIP with `FileReader`.

SF Pro / Regular must be available and render in Figma Desktop for the current Dark components. If the plugin reports a font failure, select SF Pro on a Figma text layer, accept the activation prompt if shown, and run the plugin again. The importer checks `figma.listAvailableFontsAsync()`, loads the exact returned font, and tests a temporary TextNode. It does not substitute another font. Older Package schema `0.3.0` exports lack the typography evidence needed by the current importer.

## Component scope and confirmed behavior

- **Button and Search:** native Component Sets from Package v1, with editable Button `Label` and Search `Placeholder`/`Value` properties. Their first Figma Desktop projections were validated.
- **File Explorer:** the Active row truncates a single-line label when narrowed; JSON and ZIP tagged rows keep their tags at the right; Folder Rows cover Expanded and Collapsed at observed Dark depths 0–2. The user confirmed these bounded samples in Figma Desktop on 2026-10-02 and confirmed the Tree Navigation Row consolidation on 2026-10-03.
- **Files View:** a focused excerpt of the open Dark Files scene has five header actions and nine rows. It now uses Tree Navigation Row instances and Icon Button instances inside its existing Side Panel composition. The user confirmed the consolidation in Figma Desktop on 2026-10-03. The excerpt omits repeated JSON entries, not a rule or state.
- **Bookmarks View:** a focused Dark excerpt uses the existing Bookmarks tab and Side Panel host, reuses the identical New group and Collapse all action variants from Files, and adds two own header action variants. A three-variant Bookmarks Row set represents the observed expanded group, selected nested bookmark, and multiline root bookmark with editable labels. The user accepted the hosted composition in Figma Desktop on 2026-10-03.
- **Outline View:** the existing Tree Navigation Row set gains `Kind=Outline` variants with editable multiline labels and automatic row height; Files variants keep fixed height and ellipsis. Hierarchical children frames reuse the existing Tree Navigation Guide instance so vertical lines follow wrapped descendants. The focused Dark View reuses the Side Panel slots, Workspace Tab, Bookmarks' search action, Icon Button, canonical glyphs and Appearance Variables. The user confirmed its corrected separate left-hosted resize preview in Figma Desktop on 2026-10-04; the source Outline scene was in the right sidedock.
- **View Header/Breadcrumb:** nested editable Breadcrumb Segment, Trail and Markdown View Header Components. The user accepted the Dark Markdown sample, including its documented narrow-width approximation, on 2026-10-02.
- **Workspace Tab:** a native `Context = Main | Sidedock`, `State = Active | Inactive` Component Set with editable title and swappable Sidedock icons. The first Dark version was confirmed on 2026-10-02; the full-kit Dark/Light appearance was accepted on 2026-10-03.
- **Side Panel:** the left `WorkspaceTabs / Sidedock` group and `Side Panel / Left` Component with a flexible Hosted View slot. The user confirmed the Dark 200 px expanded minimum, 16 px collapse glyph, and wider alignment on 2026-10-02. Right sidedock remains outside this sample; the full-kit Dark/Light appearance was accepted on 2026-10-03.
- **Search View:** the earlier hosted Dark composition and component reuse revision were accepted by the user. The focused 2026-10-04 extension reuses Search Filled, exposes open Search options in a second hosted preview, and adds compact controls, global Toggle/Tooltip instances, and short/expanded Match variants. Query and note text are editable sample content. The extension awaits Figma Desktop comparison.
- **Primitive consolidation, Figma validated:** Icon Button centralizes observed toolbar and Sidedock icon controls; `Icon` is an instance swap backed by tracked SVGs. The compact 24×20 Search Match case control is now a Search-specific Component Set because its inline anatomy differs. Tree Navigation Row centralizes selection, radius, typography, indent and optional trailing metadata; Files keeps fixed height/ellipsis, while Outline adds multiline height. The user confirmed the primitive structure and Dark/Light page mode switch on 2026-10-03, clarifying that the last reported error was an operation mistake. The user then accepted the expanded full-kit Dark/Light result in Figma Desktop. The focused Search hover state awaits its own Desktop check.

The focused probes in `tests/fixtures/` are projections of real Obsidian observations; the earlier full runtime captures and paired Package ZIPs remain ignored beside the exported packages. They describe bounded components and their Dark/Light visual values, not new public API specimens. The plugin's normal UI does not expose separate probe pickers or generator buttons. The user accepted the generated full-kit Dark/Light appearance in Figma Desktop on 2026-10-03; the in-plugin readback checks the bound colors and structural stability of the current scope.

The subsequent Variable-alias and canonical-glyph foundation was accepted by the user on 2026-10-03.

## Package v2 Button normal pilot

A selected **Package v2 ZIP** reveals the separate **Generate Button normal** diagnostic action and Dark/Light diagnostic JSON inputs. This retained regression path checks causal CSS binding evidence that the Package v1 UI Kit does not encode: `--button-radius`, `--interactive-normal`, and `--text-color` on one Button normal Component. It does not run the full UI Kit action or supply its appearance collection. Package v2 assembly and diagnostic commands are described in [development.md](../../docs/development.md). The generated Component and binding IDs were checked through Dark → Light → Dark in Figma Desktop on 2026-10-01. The v1 full kit now creates its own `Obsidian UI / Appearance` Variables from paired observed appearance evidence; its token roles are distinct from this Package v2 causal diagnostic.

The focused `test:search-view`, `test:side-panel`, `test:workspace-tab`, `test:view-header`, `test:folder-row`, `test:file-explorer-row`, `test:search`, `test:ui-kit`, and `test:variables` scripts cover their respective readers or model logic. Automated checks cannot establish the rendered Figma Desktop result. `dist/code.js` is ignored and regenerated locally. `src/code.ts` dispatches the plugin messages; `src/full-ui-kit-generation.ts` composes the one-action v1 flow from existing generators. `src/file-explorer-view-data.ts` reads the focused current scene and `src/file-explorer-view-generation.ts` creates its new components and hosted Files preview. `src/ui.html` presents the ZIP picker and the relevant action.
