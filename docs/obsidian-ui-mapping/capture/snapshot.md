# Canonical Mapping snapshot

Run `npm run dev`, open the development vault in Obsidian, and use **Open Obsidian UI Mapping**. The command opens or reveals the same scrollable workspace tab. This `ItemView` instantiates 26 Obsidian public API families from the shared [component registry](component-registry.md). Press **Export snapshot** to save a timestamped folder under `dev-vault/.obsidian-ui-system/ui-catalog-exports/`.

## Files

- `manifest.json`: schema version, runtime Obsidian `apiVersion`, installed `obsidian` SDK package version embedded at build time, UTC capture time, platform, mode from the body's `theme-light` or `theme-dark` class, and theme name (currently `null`). The runtime and SDK versions are independent.
- `tokens.json`: compatibility projection of the technical token evidence. It contains non-empty computed CSS custom properties from `html` and `body`; body values take precedence. It remains schema 0.4.0 and supports the existing semantic diff and Figma Package v1.
- `token-evidence.json`: separate technical format `obsidian-ui-token-evidence`, version 1, for this one captured mode. Each CSS custom-property name identifies one observation with separately computed `html` and `body` values, the selected legacy value, CSSOM declaration candidates, selectors, enclosing conditions, applicability, `var(...)` references and raw fallback text, and source diagnostics. `rawValue` is the CSSOM-declared value returned by `getPropertyValue()`, which may be browser-serialized rather than byte-for-byte original stylesheet text. Stylesheet and rule indices aid diagnosis only; they are not stable identities.
- `components.json`: 59 snapshots of 26 public API families. Each record has a stable type `id`, unique `variant` within that type, category, public API implementation name, current and known states, and a DOM tree. Each element records tag, classes, selected attributes and live form properties, direct text, rendered width/height, and selected computed styles.
- `capture-context.json`: technical format `obsidian-ui-capture-context`, version 1. It repeats the individual manifest as `environment`, records the SHA-256 of the installed compiled Mapping `main.js`, and records the window's `innerWidth`, `innerHeight`, and `devicePixelRatio`. The export checks the same context before and after capture and fails if it changes.

Export recreates all declared variants just before capture, so manual interaction with a specimen does not change the meaning of its label. Every export uses a new folder. Its files are local test output and are ignored by Git.

The token evidence uses `resolved` when a computed value exists, `no-applicable-declaration` when complete visible CSSOM coverage shows no declaration applicable to either captured scope, `unresolved` when an applicable declaration exists but no computed value does, and `unknown` when coverage or applicability prevents a conclusion. A reference is an observed syntactic dependency, including references in fallbacks that may not execute. A direct alias can be inferred only from a uniquely attributable entire declaration of the form `var(--name)` without fallback; equal computed values do not establish an alias. If rules compete, all candidates remain and attribution is `unknown`. The browser supplies computed values; Mapping does not reproduce the cascade or evaluate functions such as `calc()`.

Two technical captures can be joined in memory by property name into optional `dark` and `light` observations without synthesizing missing values. This join is not yet an export format. Figma Package v1 remains the same five-file ZIP with schema 0.4.0; older ZIPs remain valid but contain no recoverable declaration provenance or aliases.

A controlled Dark/Light set also needs one Mapping and one Layout Lab export in each mode. Compare all four context sidecars; the pure validator requires the same plugin build hash, viewport, Obsidian runtime, SDK, schema, and platform, with the expected mode on each export. Different capture timestamps are preserved. Choose one Layout export as the inference source by its mode and timestamp; the other remains raw visual evidence. A missing build file or unavailable SHA-256 fails the individual export rather than producing an unverifiable sidecar. Theme names that Obsidian does not expose remain unknown.

## Current limits

- This is one running Obsidian instance, theme mode, platform, and UI state. It does not prove how other versions, themes, or platforms render.
- `obsidianVersion` is `apiVersion` from the running app. It follows the app release cycle but is the public API version, not a separate installer build number. `obsidianSdkVersion` comes from the `obsidian` package installed during build; it can differ from runtime.
- No public API used here reliably reports the active community theme name, so `theme` is `null`.
- Token evidence includes names declared in CSSOM-accessible stylesheets or `html`/`body` inline styles, plus names directly referenced by those declarations. Computed values are captured only for `html` and `body`; component-subtree-only variables may have no value there. Browser security may hide stylesheet rules entirely, so unseen names cannot be listed. Inaccessible sheets are recorded and make absence uncertain. Dynamic changes between CSSOM enumeration and computed-style reads are not frozen by this capture.
- The snapshot records selected computed styles, rendered dimensions and selected live form properties, not every CSS declaration, interaction, pseudo-element, or semantic meaning. `states.known` lists known state names; each declared variant is separately rendered and measured.
- Direct overlays are opened only during their own capture and closed afterward. Their roots live outside the Mapping tab. `Modal` and `ConfirmationModal` use public `modalEl`; `Notice` uses public `containerEl`; `Menu` uses a narrow DOM selector because the SDK exposes no menu root. Backdrops and platform-native menu UI are outside the captured roots.
- Suggestion popovers are located by the container created during their own activation; the two suggestion modal subclasses use public `modalEl`. The bare `PopoverSuggest` exposes an empty shell only, because its public API has no item provider. Popup dimensions depend on window context.
- `setTooltip` captures the registered target with its `aria-label`, but no hover tooltip; `displayTooltip` captures the real tooltip it opens, then removes the Mapping-labelled root because the SDK has no dismiss function. `setIcon` captures its SVG inside the fixture container. Tooltip placement and the icon container's width depend on the Mapping viewport. `HoverPopover` remains limited: its SDK contract exposes no public close operation.
- `TextAreaComponent` stores its live content in the `textarea.value` property; direct text nodes are empty in the observed runtime. `DropdownComponent` renders a native `select` with `option` children; the selected value is read from the `select`, with `default` meaning the first fixture option and `selected` the second. The option `value` attributes are captured. `SliderComponent` creates a wrapper containing `span.slider-value` followed by `input.slider`; capture uses that wrapper so the inline value is included. Its fixed range is 0–100 in steps of 1, the disabled specimen holds 50, and the input's `min`, `max`, and `step` attributes are captured.
- In the observed Obsidian build, `ToggleComponent.setValue(true)` changes the component's public state and `is-enabled` class while its child input's native `checked` property remains `false`. The exported `states.current` comes from `ToggleComponent.getValue()`; `dom.properties.checked` reports the literal DOM property.
- Exports are five sequential writes. A storage failure can leave an incomplete folder; rerun the export to create a new one.
